## P3 · 2026-08-04 12:57 EDT · restarted Hammerspoon, still "(no claude sessions found)" — root cause found

cause is **output size**: `hs.task` deadlocks when the child writes more than ~512 bytes to

`exit()`/`fflush`/`write` — exactly the stack `sample` showed twice, which was pointing at
the answer the whole time.

**Threshold, measured** — seven `osascript` children under `hs.task`, each returning a
string of a known length:

## P7 · 2026-08-04 14:15 EDT · "Ask 1. Yes." — build D67

**Built as `v49`.** The join first: `safeWindowSpace` wraps `hs.spaces.windowSpaces` (which
throws like every other `hs.spaces` call), `mapSessionsToSpaces` ties each session to the
Desktop its window is on, and `sessionGroupsFor(sid)` collapses those sessions **one group
per project**. `screenEntries` then emits a *block* per Desktop rather than a line:
`Desktop N` and the icon row belong to its first line, the rest are indented under it.

Finder included, which is D7's reversal — and `rankProjects` keeps the top two, ties broken
on name so the label cannot flicker. `projectLabel` colours a **restored** Desktop's name
orange before it has been re-read, which matters because a Desktop you have not visited
today is exactly the one you are trying to find your way back to, and D3 says it cannot be
read until you go there.

report — it looked a Desktop's dot up by comparing its *label* against the set of live
session directories, which is why an open document could take a Desktop's dot away and why
a Desktop merely *called* `claude-config` wore the dot of a session two Desktops away. A
comment stands where it was, saying so.
